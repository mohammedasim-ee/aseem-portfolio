# CLAUDE.md — Aseem Portfolio + AI Digital Twin

Project guidance for anyone (human or Claude) working in this repo.

## What this project is

A personal portfolio for Mohammed Aseem (3rd-year, Digital Transformation, Atria
University) with an "AI Digital Twin" chat assistant embedded in it. The Twin
answers questions about Aseem's real background and projects from a verified
knowledge base, and explicitly refuses to invent facts it wasn't given —
general/technical questions unrelated to Aseem are answered normally, like any
AI assistant.

## Stack

Next.js (App Router) + TypeScript + Tailwind CSS. Deployed on Vercel.
AI chat calls the Anthropic Messages API server-side only (Next.js Route
Handler) — the API key never reaches the browser.

## Where things live

- `src/data/` — the single source of truth for every fact the Digital Twin
  is allowed to state (`profile.ts`, `projects.ts`, `skills.ts`, `journey.ts`).
  If a fact isn't in one of these files, the Twin must say it doesn't know,
  not guess. Update these files directly rather than asking the AI to
  "make up" a bio, resume, or extra projects.
- `src/lib/knowledgeBase.ts` — builds the system prompt and does simple
  keyword retrieval over the data files above.
- `src/lib/aiProvider.ts` — talks to the Anthropic API.
- `src/lib/emailProvider.ts` — sends contact-form emails via Resend (falls
  back to a `mailto:` link if not configured).
- `src/lib/rateLimit.ts` — basic per-IP rate limiting for both API routes.
- `src/app/api/chat/route.ts` — chat endpoint.
- `src/app/api/contact/route.ts` — contact-form endpoint.
- `src/components/` — page sections (Hero, About, Projects, Skills, Journey,
  DigitalTwin chat widget, Contact, Nav).

## Environment variables

See `.env.example`. `AI_API_KEY` is required for the chat to work;
`RESEND_API_KEY` + `CONTACT_TO_EMAIL` are optional (contact form degrades to
`mailto:` without them). Never commit `.env.local` or real keys.

## Ground rules for anyone editing this repo

1. **No fabricated personal facts.** Bio, resume, achievements, and contact
   details are placeholders until Aseem supplies the real thing — don't fill
   them in with invented content, including via the AI.
2. **Projects listed must be real and verifiable** (checked against Aseem's
   actual GitHub), each labeled honestly if its state is unclear.
3. Run `npx tsc --noEmit` and `npx eslint src --max-warnings 0` before
   considering a change done; run `npm run build` before deploying.
4. Prefer removing a fragile/untested feature over shipping it half-working —
   this project favors a smaller thing that works over a bigger thing that
   doesn't.
